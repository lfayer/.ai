# Work Modes

## Brief Extraction

When the request is underspecified, infer the working brief from:

- topic
- audience lane: ICs or leaders
- deliverable type: post, essay, memo, chapter, book section, rewrite
- intended length or scope
- thesis or takeaway
- pasted source material
- URLs to inspect
- voice mode: faithful or refined

If a detail is missing, make a reasonable assumption and state it briefly.

## Short-form Writing

Use this mode for blog posts, essays, newsletters, conference-style articles, and technical opinion pieces.

### Default workflow

1. Find the real problem.
2. Frame the misconception, weak default, or tradeoff.
3. Build one concrete example early.
4. Move from example to principle.
5. Give the recommendation.
6. Add the caveat.
7. Close with a crisp takeaway.

### Useful shapes

#### Myth-busting shape

- Hook with the common claim.
- Explain why it is incomplete.
- Show what actually matters.
- Demonstrate with an example.
- Offer the better rule.

#### Tradeoff shape

- Name the pressure or constraint.
- Explain the tempting but weak shortcut.
- Show the better tradeoff.
- Clarify when that tradeoff changes.

#### Practical explainer shape

- Define the concept in plain language.
- Show where it appears in a real system.
- Point out the failure mode.
- Show the fix or mitigation.
- End with a rule of thumb.

### Output defaults

Unless asked otherwise, produce:

1. 3 title options
2. a tight outline
3. the draft

## Long-form Writing

Use this mode for book chapters, long essays, whitepapers, and multipart series planning.

### Default workflow

1. Define the chapter promise in one sentence.
2. Decide what misconception or weak default the chapter corrects.
3. Map the section sequence before drafting.
4. Keep each section focused on one move in the argument.
5. Use examples and cases to ground abstractions.
6. Add transitions that explain why the next section exists.
7. End with a recap and a forward bridge.

### Section design

A durable long-form section often includes:

- framing or context
- definition or model
- example or case
- implication or tradeoff
- recommendation

### Long-form discipline

- Avoid writing a stack of blog posts under one chapter title.
- Maintain a single narrative spine.
- Repeat key terms consistently.
- Keep the reader oriented: where we are, why this matters, what comes next.
- Let the tone become slightly more measured in refined mode.

### Output defaults

Unless asked otherwise, produce:

1. chapter promise
2. section map
3. section summaries
4. the draft chapter or chapter section

## Rewrite and Adaptation

Use this mode when the user supplies a draft and wants it pulled toward this voice.

### Default workflow

1. Preserve facts, structure, and intent unless the user wants a deeper rewrite.
2. Identify where the draft is vague, fluffy, or too generic.
3. Sharpen the opening.
4. Replace abstract language with mechanism, consequence, or example.
5. Add tradeoffs and caveats where needed.
6. Adjust tone to faithful or refined.
7. Cut anything that sounds like marketing or management theater.

### Rewrite priorities

- first, thesis clarity
- second, paragraph flow
- third, sentence voice
- fourth, surface polish

## Audience Notes

### IC-focused pieces

Bias toward:

- code paths
- performance implications
- architecture fit
- debugging or troubleshooting logic
- instrumentation and observability
- failure modes

### Leader-focused pieces

Bias toward:

- ownership boundaries
- communication failure points
- measurement and visibility
- cost and risk
- business and customer impact
- organizational incentives

## Final Check

Before finalizing any mode, make sure the piece:

- starts with a point, not a warm-up,
- teaches something concrete,
- acknowledges tradeoffs,
- sounds like a practitioner,
- earns the confidence of a skeptical technical reader.
